# Architecture — Ultimate Tic Tac Toe

Status: **authoritative for build order and file ownership.**
Precedence: `specs/requirements.md` > `specs/ultimate.spec.md` > this file.
Where `ultimate.spec.md` fixes the engine, the AI, the worker boundary and the
wire format, this file fixes everything *around* them: who owns which file, how
Glyph gets into a browser, the exact message schema, the persistence schema, the
UI decomposition, and the measured performance envelope.

Two things in here are **proven, not proposed**: the browser build (§2, run it
yourself) and the search-depth budget (§6, run it yourself). Both ship with a
script in `tools/`.

---

## 1. Module layout and ownership

**One owner per file.** An implementer edits only the files they own. Anything
that needs a change in someone else's file is a request to that owner, not an
edit. Files marked *generated* are written by a script and must never be edited
by hand.

### 1.1 Glyph modules (`src/`)

| File | Owner | Purpose | Imports allowed |
|---|---|---|---|
| `src/xox.glyph` | **nobody — frozen (D-4)** | Classic 3x3 engine + Classic AI. Its public API and 14 `@example`s must not change. | (unchanged) |
| `src/ultimate.glyph` | **Engine** | Ultimate rules: `UState`, `legal_moves`, `apply_move`, `outcome`, `winner`, `is_terminal`, `undo`, `replay`, `encode`, `decode`, fixtures. Pure, no DOM, no `mut` visible at the API. | `std/array`, `std/option`, `std/result`, `std/string`, `xox` |
| `src/ai.glyph` | **AI** | `Difficulty`, `Plan`, `choose`, `evaluate`, `classic_choose`, `difficulty_from`. Both ladders (Ultimate + Classic) so the worker has one entry point. | `std/array`, `std/option`, `std/math`, `std/time`, `ultimate`, `xox` |
| `src/web.glyph` | **Shell** | Dev-only static server. Needs exactly one change: a generic static route so `/app.js`, `/worker.js`, `/store.js`, `/ultimate.css` and `/engine/**` are served (§2.5). | (unchanged set) |

`document`, `window`, `self`, `postMessage`. `glyph fmt src` before handing off;
`glyph check src` must end *no diagnostics* with every example passing.

**Parallelism note.** `ai` imports `ultimate`, so the AI owner is nominally
blocked on the Engine owner. They are not: `ultimate.spec.md` §3 and §6 fix
every signature. The AI owner writes against those signatures from minute one
and compiles once the Engine owner lands the module. If the AI owner needs the
module to exist earlier, the Engine owner lands the **type declarations and
`new_game` first** (a 20-line skeleton that type-checks), then fills in bodies.

## 2. The Glyph → browser build (proven)

### 2.1 What `glyph build` actually emits

Measured on `glyph 0.1.72`, this project:

```
$ glyph build src --out dist
glyph build: 14 example(s) passed.
glyph build: 4 module(s) checked, no diagnostics; 4 TypeScript file(s) emitted.
glyph build: tsc --strict passed.
```

- Output is **ESM TypeScript**: `dist/xox.ts`, `dist/web.ts`, …
- Every emitted module starts with `import "./.glyph-runtime/glyph-bootstrap";`
  and then **bare** specifiers: `import * as array from "std/array";`,
  `import { schema as __glyph_schema } from "std/schema";`,
  `import { Ok as __glyph_ok, ... } from "std/result";` — the last two are
  injected by the emitter into *every* module, whether or not the source used
  them.
- The whole stdlib is materialised as source at `dist/.glyph-runtime/std/*.ts`,
  plus `glyph-bootstrap.ts` (installs `number`, `par`, `print` on `globalThis`).
- `dist/tsconfig.json` maps `std/*` → `./.glyph-runtime/std/*` via `paths`.
  `paths` is a *type-resolution* device; tsc does not rewrite the specifier, so
  the emitted JS still says `"std/array"`. **A browser cannot resolve that.**
  Rewriting it is the build step's job.
- Browser-safety spot check of the modules the engine needs
  (`array`, `option`, `result`, `string`, `math`, `time`, `schema`,
  `glyph-bootstrap`): **zero** `node:` imports, **zero** `process` uses,
  **zero** `require(`. `std/schema.ts` imports a bare `std/result`, so the
  rewrite must run **inside `.glyph-runtime/std/` too**, not just on the
  project modules.

### 2.2 The two traps, and why `tsc` (not a type-stripper) is the compiler

1. **Bare specifiers.** Solved by rewriting (§2.3).
2. **Type-only names in value imports.** `xox.ts` contains
   `import { Option, Some, None } from "std/option";`. `Option` is a *type*;
   `std/option` exports no runtime binding named `Option`. Pure erasure
   (`node --experimental-strip-types`, `module.stripTypeScriptTypes`) keeps the
   name in the import list, and the browser then fails at **link** time with
   *"The requested module './std/option.js' does not provide an export named
   'Option'"*. This is not theoretical — the fallback path in the build script
   hit exactly that error until it was taught to prune.
   `tsc` elides type-only names during emit, so it is the primary compiler.
   `tsc` is already a hard requirement of the Glyph toolchain (`glyph doctor`
   checks for it, and `glyph build` runs `tsc --strict`), so this adds no
   dependency. A `--strip` fallback exists for machines without it; it re-derives
   each module's runtime exports and prunes the import lists itself.

No type *checking* happens in this step — `glyph build` already ran
`tsc --strict` and every `@example`. Step 2 is emit-only.

### 2.3 The pipeline

`tools/build-web.mjs`, ~330 lines, no npm dependencies, node ≥ 22:

| Step | What it does |
|---|---|
| 1 | `glyph build src --out dist` (skippable with `--no-compile`) |
| 2 | `tsc -p dist/tsconfig.json --outDir dist/.web-js --module esnext --target es2022 --noEmit false --declaration false --sourceMap false` |
| 3 | Walk the import graph from the **entry modules** (`ai`, `ultimate`, `xox`). Only reachable modules are emitted — `std/http`, `std/fs`, `std/process`, `std/sqlite` are materialised by `glyph build` but never reached, so they never enter the bundle. Entries that do not exist yet are skipped with a warning, so the script is useful *today*, before `ultimate.glyph` and `ai.glyph` are written. |
| 4 | Rewrite every specifier to a relative `.js` path and write `assets/engine/`. `"std/array"` → `"./glyph/std/array.js"`, `"./.glyph-runtime/glyph-bootstrap"` → `"./glyph/glyph-bootstrap.js"`, `"./xox"` → `"./xox.js"`. `.glyph-runtime` is renamed to `glyph` so no path component starts with a dot (static hosts hide dotted paths). Emits `package.json` (`{"type":"module"}`, inert in the browser, stops node reparsing the bundle as CJS) and `manifest.json`. |
| 5 | **Audit** (comment-stripped): fails the build on `node:`, a surviving bare `std/`, `require(`, `process.`, `document.`, `window.` — AC-41, and the runtime half of AC-14. |
| 6 | **Smoke**: loads the emitted entry inside a real `worker_threads` module worker and reports its exports. This proves the ESM graph *links and executes off the main thread* with no bundler and no import map. |

## 3. Worker protocol

Owner: **Protocol**. Files: `engine-api.js` (both threads), `worker.js`
(worker), `engine-client.js` (main thread).

### 3.1 Layering

```
app.js / ultimate-ui.js          main thread
        │  (promises)
        ▼
engine-client.js  ── postMessage ──►  worker.js
        │                                 │
        │ direct import                   │ direct import
        ▼                                 ▼
engine-api.js  ────────────────────►  engine-api.js
        │                                 │
        ▼                                 ▼
assets/engine/ultimate.js         assets/engine/ai.js → ultimate.js → xox.js
```

`engine-api.js` is imported by **both** threads. The main thread calls the cheap
pure functions on it directly (`getLegalMoves`, `applyMove`, `isTerminal` are
O(81) at worst — rendering must not round-trip through a worker). The main
thread **never** calls `chooseMove`; searching is the worker's only job
(FR-4.4).

`engine-api.js` is the only place tagged unions become plain JS. Its exports
(AC-42):

```js
getLegalMoves(state)  -> [{ board, cell }, ...]              // ascending
applyMove(state, m)   -> { ok: true, state } | { ok: false, error: { code, detail } }
getWinner(state)      -> "X" | "O" | null
isTerminal(state)     -> boolean
getOutcome(state)     -> { status: "playing"|"drawn"|"won", winner, line }
chooseMove(state, level, seed, budgetMs)
                      -> { move, score, depth, nodes } | null
encode(state) -> string          decode(text) -> { ok, state } | { ok:false, error }
```

`state` inside `engine-api` is a live `UState`; `state` on the **wire** is the
`encode` string (`"U1|X|444008"`, §7.1 of the spec). Tagged unions never cross
`postMessage`.

### 3.2 Requests (main → worker)

Every request carries a client-generated `id` (a monotonically increasing
integer is enough; it never leaves the tab).

```jsonc
{ "id": 17, "type": "choose",
  "mode": "ultimate",            // "ultimate" | "classic"
  "state": "U1|X|444008",        // ultimate: encode(); classic: 9-char board
  "turn": "X",                   // classic only — whose move the engine plays
  "level": "hard",               // "easy" | "medium" | "hard"
  "seed": 918273,                // integer; determinism (D-A5)
  "budgetMs": 1500 }             // hard cap; ignored by easy/medium

{ "id": 18, "type": "legalMoves", "state": "U1|X|4440" }
{ "id": 19, "type": "applyMove",  "state": "U1|X|4440", "move": { "board": 0, "cell": 8 } }
{ "id": 20, "type": "cancel",     "target": 17 }
{ "id": 21, "type": "ping" }     // readiness probe; answers { type: "pong" }
```

### 3.3 Responses (worker → main)

```jsonc
{ "id": 17, "type": "chosen",
  "move": { "board": 0, "cell": 8 },   // classic: { "square": 4 }
  "score": 148, "depth": 6, "nodes": 412_339,
  "elapsedMs": 1487,                    // worker-side wall clock
  "state": "U1|X|444008" }              // the post-move encode, so the UI never re-derives

{ "id": 18, "type": "result",   "value": [{ "board": 0, "cell": 0 }, ...] }
{ "id": 19, "type": "result",   "value": { "state": "U1|X|444008" } }
{ "id": 19, "type": "rejected", "error": { "code": "WrongBoard", "detail": { "required": 0, "got": 3 } } }
{ "id": 22, "type": "error",    "code": "BadRequest", "message": "unknown type \"foo\"" }
{ "id": 20, "type": "cancelled","target": 17 }
{ "id": 0,  "type": "ready",    "buildAt": "2026-08-13T…" }   // unsolicited, once, on load
```

Invariants the Protocol owner must hold:

- **Every response echoes the request `id`** (AC-44). The unsolicited `ready`
  uses `id: 0`, which is never issued to a request.
- **An illegal move is a normal response.** `applyMove` over the boundary
  returns `rejected` with the `MoveError` variant tag verbatim as `code`
  (`GameOver`, `OutOfRange`, `WrongBoard`, `BoardClosed`, `CellTaken`) and
  **never throws** (AC-43).
- **Unknown `type`, malformed payload, or a `decode` failure → `error`, and the
  worker stays alive** to answer the next request (AC-44). The whole
  `onmessage` body is wrapped in try/catch; a thrown exception becomes
  `{type:"error", code:"Internal"}`.
- **One job at a time.** The worker processes messages serially. Cancellation is
  cooperative, checked at iterative-deepening ply boundaries (D-W1); a cancelled
  job answers `cancelled`, never `chosen`.
- **The worker never sleeps** (§3.4) and never touches the DOM.

### 3.4 FR-4.4 and FR-4.6 — who owns what

- **FR-4.4 (main thread never blocks): the worker owns it.** Search runs only in
  `worker.js`. The main thread's synchronous engine calls are bounded by
  `legal_moves` (≤ 81 cells) and `apply_move` (≈ 0.6 µs, §6). AC-45 measures
  this with a `longtask` PerformanceObserver: no main-thread task > 50 ms while
  Hard thinks for 1500 ms.
- **FR-4.6 (300 ms minimum thinking delay): `engine-client.js` owns it**
  (D-A7). Sleeping in the worker would burn iterative-deepening budget and delay
  cancellation. The client records `t0 = performance.now()` when it posts
  `choose`, and resolves the promise at
  `setTimeout(resolve, Math.max(0, 300 - (performance.now() - t0)))`.
  AC-46 tests exactly this interval. `ultimate-ui.js` must apply the move
  **when the promise resolves**, never on the raw `chosen` message.

`engine-client.js`'s public surface (the contract Shell and UI-Ultimate code
against):

```js
const engine = createEngineClient();        // spawns the module worker
await engine.ready();                       // resolves on "ready" or first pong
const plan = await engine.choose({ mode, state, turn, level, seed, budgetMs });
engine.cancel();                            // cancels the in-flight choose
engine.dispose();
```

`choose` rejects only on worker death; every engine-level failure arrives as a
resolved value with an `error` field, so UI code has one path.

### 3.5 Classic through the same pipe

Classic keeps working today via `POST /api/move` in `src/web.glyph`. Once the
worker lands, `app.js` routes Classic through `engine.choose({mode:"classic"})`
→ `ai.classic_choose` → `xox.choose_move` (D-A4). This removes the last runtime
server dependency (G-4). The `/api/move` route stays for the existing
`xox.js` path until the Shell owner cuts over; `src/web.glyph` needs no logic
change either way.

## 4. Persistence schema

Owner: **Persistence** (`assets/store.js`). No DOM, no framework, synchronous.

### 4.1 Keys

All keys share the `xox.` prefix so FR-6.4's reset is a prefix sweep.

| Key | Holds | Written when |
|---|---|---|
| `xox.settings` | difficulty, sound, theme, who moves first, last mode | on any settings change |
| `xox.game.ultimate` | the in-progress Ultimate game (FR-6.1) | after every applied move, and on `visibilitychange` |
| `xox.game.classic` | the in-progress Classic game | same |
| `xox.stats` | wins/losses/draws per mode × difficulty (FR-6.2) | when a game reaches a terminal state, once |

### 4.2 Shapes (all versioned)

```jsonc
// xox.settings
{ "v": 1, "mode": "ultimate", "difficulty": "hard", "sound": false,
  "theme": "dark", "first": "X", "seed": 918273 }

// xox.game.ultimate
{ "v": 1, "save": "U1|X|444008…",   // ultimate.encode() — the move list (D-U7)
  "redo": "0812",                    // undone moves, newest last; digit pairs
  "difficulty": "hard", "human": "X",
  "startedAt": 1760000000000, "updatedAt": 1760000042000 }

// xox.game.classic
{ "v": 1, "board": "XX.O.....", "turn": "X", "you": "X", "level": "perfect" }

// xox.stats
{ "v": 1,
  "records": { "ultimate:hard": { "w": 3, "l": 5, "d": 1 },
               "ultimate:easy": { "w": 9, "l": 0, "d": 0 },
               "classic:perfect": { "w": 0, "l": 2, "d": 7 } } }
```

Three deliberate choices:

- **The game save is the move list, not the grid** (D-U7). 2 bytes per move, ≤
  166 bytes for a full game, and `decode` replays it through `apply_move`, so a
  hand-edited save cannot produce an illegal state (AC-47). A `decode` `Err` is
  a *normal* outcome: drop that key, start a fresh game, tell the user once.
- **`redo` lives in the store, not in the wire format.** This closes the spec's
  open question 12.5 without touching `encode`: `undo` pops from `save` and
  pushes onto `redo`; any new move clears `redo`. UI-5.5 survives a reload with
  no wire-format change.
- **The seed is persisted.** A restored game replays the AI's decisions
  identically (D-A5), which makes bug reports reproducible.

### 4.3 Migration and reset

- `SCHEMA = 1`. Every read goes through `readKey(key)`:
  parse → if `!obj || obj.v !== SCHEMA` → **drop the key and return null**.
  Missing, corrupt, foreign-version and wrong-shape data all take the same
  branch. No migration code exists at v1 *by design*; when v2 arrives, `readKey`
  gets one `migrate(v1 → v2)` step and the drop stays as the floor.
- Every read/write is wrapped in try/catch: Safari private mode throws on
  `setItem`, and a quota error must never break a game in progress. On write
  failure the store flips to an in-memory map and sets `store.degraded = true`;
  the Shell shows "progress won't be saved" once.
- **FR-6.4 reset-all**: `Object.keys(localStorage).filter(k => k.startsWith("xox."))`
  → `removeItem`, then reload. Confirm dialog first, and it is the only code path
  allowed to clear stats.

### 4.4 Store API (the contract for Shell and UI-Ultimate)

```js
store.settings.get() / store.settings.patch({ difficulty: "medium" })
store.game.save("ultimate", { save, redo, difficulty, human })
store.game.load("ultimate")            // → record | null  (null ⇒ start fresh)
store.game.clear("ultimate")
store.stats.record({ mode, difficulty, result: "win"|"loss"|"draw" })
store.stats.all()
store.resetAll()
```

## 5. UI component map

One shell, two modes, one worker.

### 5.1 Composition

```
index.html
├─ header (wordmark, mode switch: Classic | Ultimate)      Shell
├─ main.play
│   ├─ #classicBoard   <svg>          ← xox.js            Shell
│   └─ #ultimateBoard  <div>          ← ultimate-ui.js    UI-Ultimate
├─ aside.rail                                              Shell
│   ├─ #status      turn indicator / verdict (aria-live)
│   ├─ #difficulty  Easy | Medium | Hard        (FR-6.3)
│   ├─ #side        who moves first             (FR-6.3)
│   ├─ #tally       stats per mode+difficulty   (FR-6.2)
│   └─ actions: Undo, Redo, New game, Rules, Sound, Reset all
└─ #rulesPanel  <dialog>  Ultimate rules        (UI-5.6)   Shell
```

The mode switch toggles which board container is present and which controller is
active; the rail is shared and re-labelled. `app.js` owns every element above
except `#ultimateBoard`, whose entire subtree belongs to `ultimate-ui.js`.
That single boundary is what lets Shell and UI-Ultimate work in parallel.

The Ultimate board is **DOM, not SVG** (unlike Classic): 81 focusable
`<button>` cells inside 9 `<div class="mini">` inside one CSS grid. Buttons give
keyboard focus, touch targets and ARIA for free (UI-5.8, UI-5.9); the big X/O
overlays and the winning line are SVG layered on top with `pointer-events:none`
(UI-5.3, UI-5.7). Re-render is per-cell diffing against the previous state, not
`innerHTML` (NFR-7.2).

### 5.2 UI-5.2 — making the forced board unmistakable

This is the #1 confusion source, so it gets **five simultaneous, redundant
signals**, driven directly off `state.forced` (which the engine normalises on
write, D-U3 — the UI never re-derives it):

1. **Everything else recedes.** Non-playable minis get `opacity:.38`,
   `filter:saturate(.4)`, and `pointer-events:none`. Illegality is enforced by
   the engine (FR-3.4); dimming is a hint, never the mechanism.
2. **The target board is lifted.** The forced mini gets a 3 px accent ring in
   the side-to-move's colour (`--x`/`--o`), a raised shadow, and
   `transform: scale(1.03)`.
3. **The ring breathes.** A 1.6 s `box-shadow` pulse — the only animation on the
   board at rest, so the eye lands on it. Removed under
   `prefers-reduced-motion` (already handled in `xox.css`), where the ring goes
   solid and thicker instead.
4. **Words, not just colour.** The caption under the board reads
   *"O must play in the highlighted board"* or, on a free move,
   *"Free move — any open board"*. It is `aria-live="polite"` so screen readers
   get the same information (UI-5.9), and it carries the colourblind-safe
   signal.
5. **Free move is its own visual state.** When `forced === None`, every open
   mini gets the ring at half intensity and the caption says so — so "free move"
   never reads as "no rule is active".

Per-cell ARIA label: `"board 5 cell 3, empty, playable"` / `"board 2, won by X,
closed"`. Arrow keys move within a mini, `Shift+Arrow` jumps between minis,
`Enter`/`Space` plays.

### 5.3 Turn/verdict copy (UI-5.4)

Driven by `getOutcome`. A tiebreak win (`line: []`, D-U4) announces
*"X wins on boards won, 4–3"*; a line win announces *"X wins"* and draws the
highlight — the highlight renders **only** when `line.length === 3` (UI-5.7).

## 6. Performance risk — measured, not guessed

**The honest question:** Ultimate's state is immutable and every search node
allocates a fresh one. Does that leave Hard usable inside 1500 ms?

**The measured answer: yes — but the immutable state is not where the money
goes.** `tools/bench-search.mjs` implements the spec's engine twice, in two
idioms that are *both writable in Glyph*, and runs alpha-beta with iterative
deepening against the **real emitted `std/array`** from `assets/engine/`, so the
allocation behaviour of `array.map`/`filter`/`fold`/`push` is the real one.

- **idiomatic** — the style `src/xox.glyph` already uses and the spec's
  pseudo-code implies: `array.map(array.range(81), fn(i) …)`, `array.filter`,
  `array.fold`, closures everywhere, `array.push` for history, no `mut`.
- **tight** — the same pure functions, but each hot copy is one `array.slice`
  followed by a local `mut xs[i] = v` on the fresh copy, and each scan is a
  `for i in array.range(n)` loop with a `mut` accumulator instead of a
  map/filter/fold chain. Identical semantics, identical API, still pure at the
  boundary.

Node 24.15, Apple Silicon, 1500 ms budget per move, one worker thread:

| Engine idiom | `apply_move` | nodes/s | depth @ opening | depth @ ply 10 (forced) |
|---|---|---|---|---|
| idiomatic (all map/filter/fold) | 597 ns | 65 k | **5** | **6** |
| idiomatic + tight `apply_move` only | 66 ns | 65 k | 5 | 6 |
| idiomatic + tight `evaluate`/`legal_moves` only | 597 ns | 292 k | 6 | 7 |
| tight (both) | 66 ns | 1 345 k | **7** | **8** |

### 6.1 What the numbers say

1. **FR-3.3 is a non-issue and the spec's `UState` shape is right.** One
   `apply_move` in the idiomatic style costs **597 ns** — three small array
   allocations and ~91 pointer copies, exactly as §2.4 of the spec predicts. At
   65 k nodes/s the search spends ~4 % of its time there. **Swapping in the fast
   `apply_move` alone changes the reachable depth by zero plies.** Nobody should
   "optimise the clone". D-U6 stands as written.
2. **The cost is the closure-chain idiom in the *scanning* functions.**
   `evaluate` (72 mini-board line checks + 8 meta line checks per leaf),
   `legal_moves` and `outcome` run at every node. Writing those three as
   `for` + `mut` loops instead of `array.filter`/`fold` chains is a **4.5×**
   node-rate win on its own, and **20×** combined with the tight copy — worth
   **two extra plies**.
3. **AC-36 passes either way.** It asks for `depth >= 3` at 1500 ms and
   `depth >= 1` at 200 ms. The idiomatic engine reaches 5–6 on this machine.
   Assume a mid-range phone is 3–5× slower: **depth 4–5**, still comfortably
   above the bar. There is no crisis, and no reason to abandon immutability.
4. **But depth 5 vs depth 7 is the difference between a Hard that misses
   two-move mini-board tactics and one that does not**, and AC-39 (Hard scores
   ≥ 18/20 against Easy) gets easier with every ply. Ultimate's branching factor
   is ~5–9 on a forced move and up to ~60 on a free one, so plies are expensive
   and each one bought is worth having.

### 6.2 Recommendation (for the AI and Engine owners)

**Keep the immutable `UState` exactly as `ultimate.spec.md` §2.2 specifies.**
Do not switch to a mutable board with an undo stack; do not switch to the
81-char string. Instead, write the four hot functions in the tight idiom from
day one — no API change, no invariant change, no `mut` visible to any caller:

```glyph
// Instead of: array.map(array.range(81), fn(i) { match i == idx { … } })
pub fn place(cells: Array<Cell>, idx: number, c: Cell) -> Array<Cell> {
  let next = array.slice(cells, 0, 81)
  mut next[idx] = c            // local mutation on a copy that has not escaped
  return next
}
```

The four functions that matter, in priority order:
**`evaluate` → `legal_moves` → `mini_status`/`outcome` → `apply_move`.**
Everything else in `ultimate.glyph` (fixtures, `render`, `encode`/`decode`,
`undo`, `replay`) is cold and should stay in the readable idiom.

This idiom is **verified to compile and pass `@example`s under
`glyph 0.1.72`** — `array.slice` + `mut next[idx] = c`, `for i in
array.range(n)` with a `mut` accumulator, and a `mut` accumulator carrying an
`Option`. `glyph check` on the probe: *3 examples passed, no diagnostics,
tsc --strict passed.*

Two guard rails for the AI owner:

- Set Hard's **hard depth cap to 12** as spec'd but expect 6–8 in practice;
  never report a depth the search did not complete (D-A6).
- Re-run `node tools/bench-search.mjs` after `ultimate.glyph` lands and compare.
  If the real engine lands below **50 k nodes/s**, the tight idiom was not
  applied to the scanners — that is the first place to look, before anything
  more exotic. A transposition table (spec OQ 12.4) stays deferred; it is worth
  less than these two idiom changes and is much easier to get wrong.
